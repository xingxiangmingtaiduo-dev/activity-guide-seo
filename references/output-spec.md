# 交付语言、标题与补图格式

默认交付英语 en、印尼语 id、葡萄牙语 pt、西班牙语 es、泰语 th、繁体中文 zh-TW、越南语 vi。每种语言各一份 Markdown 和 DOCX，共 14 个文件。简体中文仅作内部基稿，用户另有要求时才交付。

以上为生成前确认中展示的默认值。用户指定其他语言或文件格式时，以已确认要求为准；所有实际输出版本仍须完整本地化。

## Discord 社群邀请

每个语言版本的文章底部都要加入本地化邀请模块。葡萄牙语（pt）和西班牙语（es）使用 `https://discord.gg/FhSaQfq6rJ`；英语（en）、印尼语（id）、泰语（th）、繁体中文（zh-TW）和越南语（vi）使用 `https://discord.gg/Agkk96vcfA`。邀请文案、链接标签和 CTA 必须翻译成目标语言，Markdown 与 DOCX 使用相同内容和链接。

默认文案含义：欢迎读者加入 Discord，获取更多福利、游戏攻略和最新资讯；社群内会更新实用内容和专属福利。不得虚构社群规模、福利数量、官方身份或保证。

文件名使用 `<slug>-<语言代码>.md` 和 `<slug>-<语言代码>.docx`。ASCII 文件名不能代替文章内部标题的翻译。

## 文件顶部顺序

每个 Markdown 和 DOCX 文件的开头先放内部 `SEO metadata` 信息块，再放 H1。metadata 给编辑和发布人员查看，不属于文章正文；H1 之后才是读者文章内容。固定顺序为：`SEO metadata` → `H1` → 正文及图片内容 → Discord 社群邀请。metadata 字段内容使用目标语言，Source URL 和官方名称可保留原样；metadata 不计入正文长度。

建议 metadata 包含：SEO Title、Slug、Primary Keyword、Long-tail Keywords、Meta Description、Tags、Language、Source、Version/更新时间、Checked 日期（有依据时填写）。Markdown 和 DOCX 必须显示同一份 metadata，不能只在正文末尾列出，也不能让 H1 出现在 metadata 之前。

## 标题检查

每份文件的文章标题、SEO Title、H1、小标题、摘要、CTA、图片说明和图注都必须使用目标语言。SEO 字段名可保留技术标签，字段内容必须本地化。游戏和产品官方名称可以保留原名。

生成前维护内部标题清单：语言代码、文章标题、SEO Title、H1。保存后重新读取 Markdown 和 DOCX，检查实际标题，不能只检查正文。DOCX 的文章 H1、页眉（如有）和文档标题属性也必须本地化；metadata 按目标语言填写。

## 图片占位说明

图片未能下载或无法正常插入时，在相关段落后添加可见提示块。若能确认图片直链，必须在提示块中放置可点击链接；下面的中文只说明格式，交付时需把所有标签和内容翻译成目标语言：

> **待添加图片 1**
>
> **建议画面：** 添加本次活动的奖励展示图，优先选择来源网页中与本段对应的图片。
>
> **用途：** 帮助读者了解本段介绍的奖励。
>
> **来源：** 参考文章的已确认链接。
>
> **图片链接：** 有已确认的图片直链就填写为可点击链接；如果只能确认文章页面，提供文章链接并注明“未能确认直接图片链接”；不得编造链接。
>
> **建议图注：** 本次活动的奖励一览。

依据文章内容填写具体画面和用途，不能把奖励示例复制到所有文章。未看过图片时使用“建议添加……”而非描述不存在的细节。Markdown 使用引用块，DOCX 使用可见提示段落。编号和位置在两种格式中一致。补图提示不计入正文长度。

下载成功时，用真实图片和本地化图注替换提示块。下载失败但确认了图片直链时，保留本地化补图说明并提供可点击直链。只有检查图片文件、Markdown 路径和 DOCX 嵌入效果之后，才能报告“已插入”。
